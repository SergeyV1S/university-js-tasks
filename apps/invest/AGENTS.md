# Правила Invest

## Язык и стиль

- Пиши приложение, конфигурацию и тесты на TypeScript. Используй `.tsx` для файлов с JSX и `.ts` для остальных файлов TypeScript. Для хука главной страницы используй согласованное имя `useHomePage.tsx`. TypeScript для исходников приложения разрешён проверяющим. [НФТ-03](./docs/non-functional-requirements.md#согласованные-решения)
- Объявляй функции и компоненты стрелочными функциями. Именованные функции присваивай константам.

## Модули

- Размещай каждый экран в `src/pages/<имя-страницы>/` с файлами `page.tsx`, `route.ts` (или `route.tsx`) и `index.ts`. Создавай `components/`, `helpers/`, `types/`, `api/`, `hooks/` и другие подпапки по мере появления соответствующего кода.
- В UI-компонентах, включая `page.tsx`, оставляй JSX, условия отрисовки и привязки пропсов. Состояние, refs, эффекты, подготовку данных и действия выноси в хуки с именем `use<ИмяКомпонента>`. Хуки страницы и её компонентов размещай в `src/pages/<имя-страницы>/hooks/`, например `useHomePage` и `useMarketMetrics`. Хуки оболочки и общих компонентов размещай в `src/app/hooks/` и `src/shared/hooks/` соответственно. Типы пропсов держи рядом с компонентом. Расчёты PnL, стоимости и конвертации оформляй чистыми функциями и вызывай их из хуков или слоя данных.
- Передавай в JSX готовые именованные обработчики событий через `onClick={closeExplanation}`, `onPointerLeave={handlePointerLeave}` и аналогичные пропсы. Объявляй обработчики в соответствующем хуке. Если обработчику нужен элемент списка, привязывай его там же.
- Экспортируй из `index.ts` конфигурацию маршрута и другие данные только по необходимости внешнего использования. Импортируй модуль страницы извне через его `index.ts`. Страницы используют общие модули через `shared/`.
- Размещай переиспользуемые функции, хелперы и утилиты в соответствующих подпапках `src/shared/`, даже если пока у них один потребитель. Например, держи `debounce` и общее форматирование в `src/shared/helpers/`. Общий клиент и общую политику рыночных запросов держи в `src/shared/market/`. Клиент формирует запросы, нормализует ответы и ошибки провайдера. Сценарии конкретного экрана остаются в его модуле.

## Стили Tailwind CSS

- Используй канонические классы Tailwind CSS и токены темы по правилу `tailwindcss(suggestCanonicalClasses)`. Например, для 89 px используй `w-22.25`. Запись в квадратных скобках оставляй для значений, которые нельзя выразить эквивалентным классом или существующим токеном.

## Маршрутизация и состояние

- Используй React Router в Data Mode. Храни шаблоны в `PATHS` в `src/shared/constants/router-paths.ts`. Собирай маршруты через `createBrowserRouter` в `src/app/router.tsx` и подключай `RouterProvider` в `src/main.tsx`.
- Используй URL `/`, `/coin/:coinId` и `/portfolio`. Хостинг сборки должен отдавать `index.html` при прямом открытии вложенного маршрута приложения. Проверяй прямое открытие и перезагрузку на опубликованной сборке.
- Используй route loaders для начального чтения данных. Передавай `request.signal` в операции, которые поддерживают отмену. Возвращай типизированный результат, включая состояния ожидаемых ошибок. Показывай Skeleton во время начальной загрузки и освобождай его при завершении запроса или ошибке.
- После открытия экрана хук подключает результат loader к экрану и подписывается на Zustand. Actions Zustand управляют поиском, сменой периода и валюты, опросом, повторами и покупками. Начальные данные используются без повторного запроса из хука. При уходе со страницы останавливай её таймеры и отменяй устаревшие чтения. При смене параметров применяй только актуальные ответы.
- Храни прикладное состояние в Zustand. Для взаимодействия с интерфейсом используй локальное состояние в хуках компонентов.

## Портфель и рыночная квота

- Подтверждай покупку после успешной записи в `localStorage` под Web Locks с проверкой ревизии. Отправляй уведомление о ревизии через `BroadcastChannel` после записи. Сбой уведомления обрабатывай отдельно от результата сохранения. Перечитывай снимок при возвращении во вкладку.
- Проверяй Web Locks на всех обязательных платформах. При недоступности оставляй чтение портфеля доступным при исправном хранилище и блокируй добавление с пояснением. Приёмка сохранения на такой платформе остаётся незавершённой.
- Проверяй НФТ-26 по приёмочному сценарию с двумя вкладками и применимым окнам тарифа. [Сценарий и подсчёт запросов](./docs/implementation-plan.md#задача-8-сквозная-учебная-приёмка)
